# Test strategy (next platform, track N)

Rules (AGENTS.md "Testing changes that call models", track O §1):
behaviour is tested with the scripted model (`tests/pipeline.test.ts`
pattern), PGlite (`tests/db/harness.ts`), connector fixtures
(`tests/connectors/fixtures.ts`), the local **fixture MCP server**
(`tests/fixtures/mcp/server.ts`, new) and mocks. **No real model, MCP
server, connector, site or call** in `npm test`. Write each test first and
see it fail. New tests go in `tests/next/` (behaviour) and
`tests/db/next-*.test.ts` (SQL, RLS).

## 2. The fixture MCP server

A Node `http` server started in-process by the tests (no new dependency;
it speaks the JSON-RPC shapes `@ai-sdk/mcp` sends, recorded from the AI SDK
docs and the client's types). Host names map to it in code, never from
env (the `browser/egress.ts` rule). Tools:

| Fixture tool        | Behaviour                                                                                    | Used by               |
| ------------------- | -------------------------------------------------------------------------------------------- | --------------------- |

| `create_item`       | Write, returns `structuredContent.id`                                                        | NT-MCP-02, NT-DLV-04  |
| `get_item`          | Read used as the read-back                                                                   | NT-MCP-05             |
| `poisoned`          | Description with model-directed instructions                                                 | NT-MCP-03             |
