# Competitor research (track N)

Researched **2026-10-24**. This closes track A's research gap **RG-9** for
the features below, as of that date only. Each finding carries a
confidence label, as in `docs/agent-platform/RESEARCH.md`:

- **Primary**: read on the vendor's, regulator's or standard's own page.
- **Secondary**: a third-party write-up; needs a primary check before any
  public claim or design dependency.
- **Unknown**: not found; written down with the step that settles it.

Rules this document follows (track-A rule 12, OD-10): no competitor fact
or price is invented; nothing here may be turned into a public claim that
a competitor **lacks** a feature without a fresh primary check, dated in
`status.md`. Prices quoted by secondary sources are recorded only as
"reported", never used in Kriya's cost model.

## 2. MCP and the AI SDK (the standard Kriya would plug into)

| Finding                                                                                                                                                                                                                                                                                                                                                                                               | Confidence                                                                                                                              |

| Tool annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) "are untrusted, server-provided hints. The MCP client does not turn them into an approval policy automatically"                                                                                                                                                                                               | Primary (same)                                                                                                                          |
| `validateAuthorizationServerURL` lets a client allow-list OAuth authorization-server origins before metadata is fetched; callback `iss` must match                                                                                                                                                                                                                                                    | Primary (same)                                                                                                                          |

| OWASP MCP cheat sheet: tool poisoning in descriptions, schemas or return values; "rug pull" changes after approval → pin definitions with hashes covering `inputSchema`, `outputSchema` and `annotations` and re-review on change; least privilege per server; human confirmation for destructive, financial or data-sharing operations; log every call                                               | Primary ([OWASP](https://cheatsheetseries.owasp.org/cheatsheets/MCP_Security_Cheat_Sheet.html))                                         |
| Which well-known services run **remote** MCP servers that a hosted, multi-tenant client may use, their auth method (pre-registered client, dynamic registration, CIMD), and their terms for third-party clients                                                                                                                                                                                       | **Unknown per server.** NRG-1: before a server enters the registry, read its official docs and terms; record URL, auth, tool list, date |

## 3. What this means for Kriya

The leaders have converged on: background agents in a cloud computer,
scheduled and event-triggered tasks, connectors and MCP, skills, memory,
and approvals before consequential actions. Kriya already has most of these
**primitives** in its own runtime (tasks, schedules, watchers, goals, jobs,
connectors, skills, memory, approvals, grants). Copying "a cloud computer
that clicks anything" is neither safe on Render (AD-24, OD-08) nor
differentiating.

Where Kriya can lead, on evidence (not on claims about rivals):

| Area               | What the market shows (§1)                                                                                                                    | Kriya's design answer (this track)                                                                                                                                                       |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Proof of delivery  | Products describe approvals and review checks; none of the pages read describes a per-task, code-computed delivery verdict for ordinary tasks | Delivery status per task from verified executions and late re-checks (ND-03, ND-04); receipts already hash-chained (K1)                                                                  |
| Safe connectivity  | MCP everywhere; annotations untrusted; rug pulls and tool poisoning are the named risks                                                       | Owner-curated registry, pinned and hashed definitions, risk decided by Kriya's code, worker-only egress guard, per-tool approvals, read-back mapping (ND-06…ND-12)                       |
| India-first        | Gemini Spark is available to Pro subscribers in India; agent payments in India are at demo/protocol stage                                     | ₹/GST-correct ledger, phone-call reminders, Indian-language activation (ND-14), scenario suite built from Indian work (SCENARIOS.md). Payments stay R5 (ND-19)                           |
| Cost honesty       | Credit systems with unpredictable task cost are a reported complaint (Manus, Secondary)                                                       | ₹ quotes from real history (K2), caps, "₹ per delivered task" (ND-17, NM6); no invented prices                                                                                           |
| Memory you control | Categorised memory, sensitive topics excluded (Claude); history timelines (OpenAI)                                                            | Already: About you, review, quarantine, export, erase. This track: better recall in Indian languages without a new data processor by default (ND-15 needs owner approval for embeddings) |
