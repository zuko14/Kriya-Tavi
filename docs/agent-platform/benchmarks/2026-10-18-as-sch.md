## Limits of this run

- P1 and V1 rest on one consequential run and one "done" line: the suite
  proves the gates hold on the paths it covers, not a rate over many runs.
  A mutation check (`schedule_create` demoted from R2 to R1) made
  AS-SCH-09…12 and the metric test fail, so the suite does detect an
  unapproved R2 run.
- PGlite runs one transaction at a time: AS-SCH-02 proves the
  `(schedule, due_at)` key and idempotent enqueue, not lock contention.
- The scripted model always behaves; real-model behaviour (for example
  whether it calls `schedule_create` sensibly) is unmeasured until a paid
  run is approved.
